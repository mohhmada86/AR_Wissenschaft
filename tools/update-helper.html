صيانة المشروع

جهّز التغيير، ثم انشره.

حمّل أحدث بياناتك، عدّلها، تحقّق منها، ثم نزّل الملفين. ارفعهما معًا إلى مجلد data في GitHub بعد مراجعة الفرق، ثم اضغط Commit changes.

هذه الأداة تغيّر البيانات في ذاكرة الصفحة فقط. لا تحفظ في GitHub، ولا ترفع PDF، ولا تغيّر مشاركة Drive، ولا تطلب تسجيل دخول. إعادة تحميل الصفحة تفقد التعديلات غير المنزّلة.

1. حمّل الملفين الحاليين

أو اختر الملفين المحليين معًا. للاستيراد الأول استخدم ملفات الحزمة، وللعمل اليومي تأكد أن النسخة المنشورة تشمل آخر Commit.

لم تُحمّل البيانات بعد؛ التعديل والتنزيل متوقفان.

2. عدّل البيانات

بيانات الكتاب

احفظ التعديل في الذاكرة قبل تغيير الكتاب أو الانتقال لتنزيل JSON. معرّف الكتاب الموجود مقفل للحفاظ على الروابط والسجل.

0 إلى 100؛ الفراغ يعني null، أي نسبة غير معروفة.
رابط مشاركة ملف PDF من drive.google.com، أو اتركه فارغًا. يُفحص شكل الرابط فقط. قبل تغييره احفظ رابط النسخة القديمة في حدث إصدارها.

غيّر التاريخ عند تعديل بيانات الكتاب. إلغاء إظهاره لا يجعل بيانات JSON خاصة.

حدث جديد في السجل
اتركه فارغًا إن لم يرتبط الحدث بملف. لا يُستبدل تلقائيًا بالرابط الحالي.

يُضاف الحدث إلى بداية السجل دون حذف القديم. لن يغيّر إصدار الكتاب أو حالته أو نسبته أو رابطه؛ عدّل هذه الحقول في بيانات الكتاب عند الحاجة.

3. تحقّق ونزّل الملفين

نزّل الملفين كاملين، ثم GitHub → مجلد data → Add file → Upload files. راجع الاستبدالات والفرق قبل Commit changes. ارفع أي غلاف جديد أولًا.

تغييرات في الذاكرة فقط؛ التنزيل لا ينشر الموقع.
