# مشروع القراءة والمراجعة الجماعية

موقع عربي ثابت لعرض الكتب وإصداراتها وروابط مراجعتها. يعمل مباشرة على GitHub Pages دون تثبيت برامج أو تشغيل build. الصفحة الرئيسية مدخل مبسط يعرض المجالات و5 كتب مختارة فقط، بينما يعرض `catalog.html` الفهرس الكامل والبحث والفلاتر. ومن كل صفحة كتاب ينتقل القارئ إلى `review.html` لإرسال ملاحظة دقيقة مرتبطة بالكتاب والصفحة.

## أين توجد الأشياء؟

| المكان | ما يحتويه |
| --- | --- |
| GitHub | صفحات الموقع وتصميمه وصور الأغلفة وملفات JSON والأدلة وسجل تغييرات المصدر |
| Google Drive | ملفات PDF وروابط مشاركتها والتعليقات على كل ملف |
| جهازك | نسخ احتياطية من المصدر القابل للتحرير وملفات PDF المنشورة |

الموقع يشتق تلقائيًا المجالات وأعدادها والكتب الخمسة المختارة والفلاتر وعدد النتائج وتاريخ آخر تحديث ظاهر. تكتب أنت بيانات الكتب ونسبة المراجعة والحالة والنسخة والروابط والأحداث؛ لا توجد مزامنة لتعليقات Drive. نموذج الرأي العام ونموذج مراجعة الكتاب يستخدمان Supabase عند إضافة القيمتين العامتين؛ وإلا فالحفظ محلي على جهاز الزائر فقط. الواجهة لا تستخدم تسجيل دخول أو تحليلات أو مكتبات خارجية.

| ما تريد تغييره | الملف أو الحقل |
| --- | --- |
| اسم المشروع والمقدمة والتعريف | `data/site.json`: `title`, `intro`, `about` |
| رابط المستودع ورابط الموقع | `data/site.json`: `github_url`, `site_url` |
| الكتاب والعنوان والمؤلف والتخصص والوصف | `data/books.json`: `id`, `title_ar`, `title_en`, `author`, `category`, `description` |
| الحالة والنسخة والنسبة والرابط الحالي | `data/books.json`: `status`, `version`, `progress`, `drive_url` |
| تاريخ تعديل بيانات الكتاب | `data/books.json`: `last_updated` |
| صورة الغلاف | ملف داخل `assets/covers/` ومساره في `cover` |
| إظهار الكتاب أو تمييزه كمثال | `enabled`, `demo` في `data/books.json` |
| الأحداث وروابط الإصدارات التاريخية | `data/updates.json` |
| تفعيل التعليقات والمراجعات المشتركة | SQL ثم القيمتان العامتان في `data/comments-config.js` |

إضافة مجال جديد لا تحتاج إلى تعديل HTML أو JavaScript: أضف كتابًا ظاهرًا بقيمة `category` الجديدة إلى `data/books.json`، وسيظهر المجال وعدده تلقائيًا في الصفحة الرئيسية والفهرس. اختيار الكتب الخمسة ثابت وآلي؛ يفضّل مجالًا مختلفًا وغلافًا حقيقيًا ويحافظ على ترتيب البيانات عند التعادل.

`id` ثابت وليس عنوانًا: أمثلة مناسبة `serway-physics-9` و`cheng-field-wave-2` و`language-learning-notes`. تغيير العنوان لا يستدعي تغيير المعرّف. لا تنسخ معرّف كتاب موجود.

## من الصفر إلى موقع منشور

1. افتح [GitHub](https://github.com/)، أنشئ حسابًا عبر Sign up، ثم أكّد بريدك من رسالة التحقق. لا تشارك كلمة المرور أو الرموز في الدردشة.
2. من زر `+` اختر `New repository`. استخدم مثلًا `book-review`، وحدّد `Public` للمسار البسيط مع GitHub Free، وفعّل `Add README` لإنشاء الفرع، ثم `Create repository`. ستستبدل README الأول بالملف الموجود في الحزمة. [إنشاء موقع GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site).
3. فك ضغط الحزمة على جهازك. افتح المجلد الناتج واسحب **محتوياته** إلى المستودع عبر `Add file → Upload files`. احتفظ بالمجلدات `data` و`assets` و`tools`. راجع الأسماء، واكتب رسالة، ثم `Commit changes` إلى `main` إذا كان ذلك مسموحًا. إذا ظهرت `Propose changes` فأنت تحفظ في فرع جديد: أنشئ Pull request وراجعه وادمجه كي يصل التغيير إلى `main`. لا ترفع ZIP ليكون الموقع، ولا تضع الملفات داخل مجلد إضافي. [رفع الملفات من المتصفح](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository).
4. في تبويب `Code` يجب أن ترى `index.html` مباشرة في جذر المستودع. تأكد من وجود `.nojekyll`؛ إن فات أثناء الرفع: `Add file → Create new file`، اكتب الاسم `.nojekyll` دون امتداد إضافي، اترك المحتوى فارغًا، ثم `Commit changes`. [ملف تعطيل Jekyll](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site).
5. افتح `Settings → Pages → Build and deployment`. اختر `Source: Deploy from a branch`، ثم `Branch: main`، و`Folder: /(root)`، واضغط `Save`. انتظر اكتمال النشر ثم افتح **العنوان الفعلي الذي يعرضه GitHub**. الحفظ اللاحق في فرع النشر ينشر التعديلات تلقائيًا. لا تحتاج ملف Actions YAML خاصًا؛ قد ترى عملية Pages الداخلية في تبويب `Actions`. النشر ليس فوريًا. [إعداد مصدر النشر](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).
6. افتح الموقع من هاتفك، ثم صفحة كتاب ورابط سجل تحديثاته. افتح أداة الصيانة من التذييل، وحمّل البيانات المنشورة قبل أول تعديل. راجع تقرير الاختبار داخل الحزمة لتعرف ما يلزم التحقق منه في حسابك.

| اسم المستودع | عنوان النشر المتوقع — أمثلة شكلية، استبدل الأسماء |
| --- | --- |
| `USERNAME.github.io` | `https://USERNAME.github.io/` |
| `PROJECT-NAME` مثل `book-review` | `https://USERNAME.github.io/PROJECT-NAME/` |

في الخيار الأول، استخدم اسم حسابك الفعلي بحروف صغيرة. الحزمة نفسها تعمل في الخيارين دون تغيير الكود. لا تضع `/` في بداية مسارات `assets` أو `data` ولا تربط التنقل بقيمة `site_url`.

## تخصيص المشروع مرة واحدة

هذه النسخة لا تحتوي على كتب تجريبية. أضف كل كتاب حقيقي بمعرّف دائم وفريد، واجعل `demo: false` و`enabled: true`. ابدأ دائمًا من أحدث `books.json` و`updates.json` المنشورين قبل أي تعديل.

افتح `data → site.json → Edit` وعدّل `title`, `intro`, `about`. اترك `github_url` و`site_url` فارغين إلى أن تعرف الرابطين الحقيقيين. `github_url` يقبل HTTPS من `github.com`؛ و`site_url` هو رابط قاعدة الموقع المنشور كاملًا **مع مسار المستودع والشرطة `/` الأخيرة**. هو للبيانات الوصفية وليس لتشغيل التنقل.

لأن بعض زواحف المشاركة لا تشغّل JavaScript، عدّل مرة واحدة أيضًا في **كل من** `index.html` و`book.html` داخل `<head>`: نص `<title>`، و`meta name="description"`، و`og:title` و`og:description`. اجعل عنوان صفحة التفاصيل ثابتًا عامًا مثل «تفاصيل الكتاب | اسم المشروع»؛ يُحدّث عنوان المتصفح بعد معرفة الكتاب. عند معرفة الرابط، يمكنك إضافة `<meta property="og:url" content="…">` برابط قاعدة المشروع الحقيقي الكامل في الصفحتين. استبدل علامة الحذف بالرابط الفعلي؛ لا تضف رابطًا وهميًا. حدّث كذلك نص اسم المشروع والمقدمة والتعريف الثابتة في HTML إن أردت أن تطابق إعداداتك حتى عند فشل تحميل `site.json`.

المعاينة الاجتماعية عامة للمشروع: `book.html?id=...` لا يضمن صورة أو عنوان مشاركة خاصًا بكل كتاب عن طريق JavaScript وحده. لا توجد صورة مشاركة موعودة أو ملف صورة غير موجود. أيقونة الموقع محلية ومرفقة.

## طريقة الصيانة الموصى بها

استخدم الأداة لتجنب أخطاء الفواصل:

1. انتظر وصول آخر تعديل GitHub إلى الموقع، ثم افتح أداة الصيانة واضغط «تحميل أحدث البيانات المنشورة». أو استورد **الملفين الحاليين** المحليين عبر خانتي `books.json` و`updates.json`.
2. اختر «إضافة أو تعديل كتاب» أو «إضافة تحديث». املأ الحقول، ثم اضغط زر الحفظ **في الذاكرة**. إضافة حدث لا تغيّر بيانات الكتاب الحالية.
3. اضغط «التحقق وتجهيز JSON». راجع المحتوى، ثم نزّل `books.json` و`updates.json`. إذا أضاف المتصفح `(1)` للاسم، أعد تسميته للاسم الدقيق قبل الرفع.
4. ارفع الأغلفة الجديدة أولًا. افتح المستودع → `data → Add file → Upload files`، وارفع **الملفين كاملين معًا**. راجع الملفين والاستبدالات قبل `Commit changes` في التزام واحد. إذا لم تعرض شاشة الرفع فرقًا تفصيليًا، قارن النص المولّد بالملفين الحاليين أو استخدم فرعًا جديدًا وراجع `Files changed` في Pull request قبل دمجه.
5. انتظر النشر وأعد تحميل الموقع وتأكد من التغيير. لا تتابع التعديل من نسخة محلية قديمة؛ حمّل أحدث الملفين كل مرة. عند وجود أكثر من مسؤول نسّقوا التعديلات لتجنب أن يستبدل أحدكم عمل الآخر.

الأداة لا ترفع شيئًا ولا تحفظ تلقائيًا. الحقول غير المحفوظة في النموذج لا تدخل التصدير. فشل تحميل البيانات لا يتحول إلى مصفوفات فارغة. تحفظ الأداة الحقول الإضافية الموجودة في سجلاتك حتى لو لم تعرض حقولًا لتحريرها. الإصلاح اليدوي متاح من `Edit` لكل JSON؛ تعديل ملفين منفصلين بهذه الطريقة قد يحتاج التزامين، ولا تجمعهما GitHub تلقائيًا.

## قوائم العمل اليومية

**كتاب جديد بأقل خطوات**

- جهّز PDF ومشاركته، ثم ارفع الغلاف إن وجد.
- حمّل البيانات في الأداة، أضف الكتاب بمعرّف دائم و`demo: false`، واحفظه في الذاكرة.
- عند أول PDF منشور أضف حدث `release` بنفس `book_id` والنسخة والرابط، ثم نزّل وارفع الملفين معًا.

**إصدار جديد لكتاب موجود**

- احتفظ برابط النسخة القديمة في حدث إصدارها وبملفها وتعليقاتها على Drive.
- ارفع PDF الجديد كملف جديد، واختبر مشاركته.
- غيّر النسخة والرابط والحالة والنسبة وتاريخ تعديل الكتاب، وأضف حدث `release` جديدًا، ثم انشر الملفين معًا.

**تصحيح بيانات فقط**

- عدّل الوصف أو المؤلف أو الغلاف أو أي حقل يحتاج تصحيحًا، وعدّل `last_updated` إلى يوم التعديل الفعلي.
- لا ترفع رقم الإصدار لمجرد إصلاح نص في بطاقة الموقع. سجل حدث `note` إذا كان مفيدًا، ثم انشر.

**إنهاء جولة مراجعة PDF**

- صنّف التعليقات وصحّح المصدر القابل للتحرير، واحتفظ بالملاحظات العالقة مع مراجع النسخة والصفحة.
- احتفظ بملف Drive الأصلي وتعليقاته؛ أنشئ PDF برقم نسخة مناسب وارفعه كملف جديد.
- ثبّت الروابط القديمة في السجل، ثم حدّث الرابط الحالي وأضف حدث الإصدار الجديد. استخدم «Resolve» للملاحظات المعالَجة عند ملاءمته، دون حذف تاريخ النقاش.
- احتفظ بنسخة محلية من المصدر وPDF. التفاصيل والبديل في [دليل Drive](GOOGLE_DRIVE_SETUP.md).

## قواعد النسخ والتواريخ

- `v1.1` ثم `v1.2` للتصحيحات المتدرجة؛ `v2.0` لمراجعة/ترجمة أُعيد العمل فيها بصورة كبيرة. انتهاء جولة لا يفرض زيادة الرقم الرئيسي.
- `last_updated` لتعديل سجل الكتاب نفسه. الحدث وحده يقدّم التاريخ الظاهر إذا كان أحدث، دون تعديل تاريخ الكتاب أيضًا.
- التاريخ الظاهر هو الأكبر بين تاريخ سجل الكتاب وتواريخ أحداثه الصالحة؛ يُستخدم نفسه للبطاقة والتفاصيل والترتيب. لا توجد خانة تاريخ مشتق إضافية.
- أدخل الأحداث الجديدة في بداية `updates.json`. الترتيب تنازلي بالتاريخ، وعند تساويه يحافظ على ترتيب المصفوفة.
- لا يعيد حدث قديم تعيين الإصدار الحالي. لا ينسخ الموقع رابط القراءة الحالي إلى حدث بلا رابط.
- الأرقام 0–9، والتواريخ ميلادية. استخدم `YYYY-MM-DD` و`progress` كرقم أو `null`. المعاينة المحلية عبر `file://` غير مدعومة لأن التحميل يحتاج HTTP(S)؛ معاينتك اليومية هي GitHub Pages.

## النسخ الاحتياطي

قبل تغيير كبير: المستودع → `Code → Download ZIP`. هذه نسخة من مصدر الموقع، وليست نسخة من PDF أو تعليقات Drive. احتفظ بالمصدر القابل للتحرير وملفات PDF على جهازك أيضًا. استرجاع ملف واحد دون تغيير بقية العمل مشروح في [حل المشكلات](TROUBLESHOOTING.md).
